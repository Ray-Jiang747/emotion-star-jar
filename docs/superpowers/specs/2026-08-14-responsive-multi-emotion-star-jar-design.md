# 多端响应式多情绪星星瓶设计规格

## 目标

将现有“生气星星瓶”扩展为能够记录多种情绪的“情绪星星瓶”，并重构响应式布局，使同一套页面在手机、平板和桌面浏览器中保持清晰、稳定、可操作。

本阶段继续使用 GitHub Pages 托管，记录仍保存在当前浏览器的 `localStorage` 中。不加入账号、云端同步或管理后台。

## 产品定位与文案

产品不再暗示情绪一定是生气，也不要求每一种情绪都必须被“解决”。核心表达调整为：观察情绪、记录经历，并选择如何回应或照顾这份情绪。

主要文案调整：

- 标题保持“情绪星星瓶”。
- 主标语改为“把每一种情绪折成星星，慢慢认识自己”。
- “为什么生气？”改为“发生了什么？”。
- “生气是正常的情绪”改为“每一种情绪都值得被看见，它们正在告诉你一些重要的事”。
- “抽一颗生气星星”改为“打开一颗情绪星星”。
- “解决方法”改为“我想怎样回应这份情绪？”。
- “让这颗星星化成星光”改为“收好这份回应”。
- “已解决记录”改为“成长记录”。
- 待处理状态在界面中称为“待回应”，完成状态称为“已回应”。

## 情绪模型

写星星时提供七个情绪选项：

1. 开心
2. 平静
3. 难过
4. 焦虑
5. 委屈
6. 生气
7. 其他

选择“其他”后显示一个简短的自定义情绪名称输入框。每种预设情绪使用稳定的颜色和图标提示，但颜色不是唯一识别方式，文字标签必须始终可见，以满足无障碍和色觉差异需求。

每条记录包含：情绪类型、自定义情绪名称、事件标题、事件描述、强度、颜色、创建时间、回应内容、回应时间和状态。

现有记录没有情绪字段。读取旧记录时将其兼容为“生气”，不重写或丢弃旧数据。现有 `pending` / `resolved` 内部状态暂时保留，以避免破坏本地数据，仅替换界面文案。

## 用户流程

### 记录情绪

用户选择情绪类型，填写事件与感受，设置强度，并完成折星流程。星星放入瓶中后进入“待回应”状态。

### 回看与回应

用户可以随机打开一颗待回应星星，查看当时的情绪、事件和强度。用户可以暂时放回瓶中，也可以写下如何回应、照顾或纪念这份情绪，然后将其收入成长记录。

正向情绪同样可以被回应，例如记录“我想记住什么”或“我想如何延续这份感受”，不使用问题化或病理化措辞。

### 成长记录

成长记录展示所有已回应星星，可按情绪类型筛选。记录卡片显示情绪名称、事件、强度、日期和回应内容。

## 响应式布局

采用单一 DOM 结构和移动优先 CSS，不维护独立的手机与桌面页面。

### 手机：360–767px

- 使用单列布局，内容顺序为头部、导航、当前主要任务、辅助信息。
- 表单、折星过程、瓶子和成长记录均占满可用宽度。
- 导航保持容易触达，但不得遮挡正文；使用 `env(safe-area-inset-bottom)` 适配全面屏。
- 主要按钮高度不小于 44px，输入控件字体不小于 16px，避免 iOS 自动缩放。
- 卡片、图片和动画不得造成水平滚动；最小支持宽度为 320px。

### 平板：768–1099px

- 使用两列布局，不压缩桌面三栏。
- 主要任务区占较宽列，瓶子或说明信息进入辅助列。
- 竖屏和平板横屏均不得出现卡片重叠、文字截断或固定高度溢出。

### 桌面：1100px 及以上

- 保留当前多栏视觉结构，内容容器设置最大宽度并水平居中。
- 在 1366、1440 和 1920 宽度下保持合理留白。
- 高度不足时允许自然页面滚动，不依赖固定视口高度容纳全部内容。

### 通用规则

- 使用 CSS 自定义属性统一字体、间距、圆角和容器尺寸。
- 使用 `clamp()` 控制标题和关键视觉尺寸。
- 图片使用明确的宽高比例和 `object-fit`，防止加载前后布局跳动。
- 动画尊重 `prefers-reduced-motion`，减少动态偏好下关闭非必要位移和循环动画。
- 主流 Chrome、Edge、Safari 和 Firefox 中保持功能可用；渐进增强效果不得成为完成操作的前提。

## 组件边界

- `star-store`：负责数据规范化、旧记录兼容、创建和回应记录。
- `emotion-catalog`：集中定义预设情绪、颜色和展示文案。
- 主应用：负责视图切换、表单交互和数据渲染，不重复定义情绪规则。
- 样式层：通过响应式布局容器控制排列，不在 JavaScript 中根据窗口宽度切换页面结构。

## 错误处理

- 未选择情绪时阻止提交并给出明确提示。
- 选择“其他”但未填写名称时阻止提交。
- 事件描述为空时保持现有必填提示。
- 本地数据损坏时回退为空列表，不让页面崩溃；旧格式记录应正常展示。
- 本地存储写入失败时显示错误提示，不虚假显示保存成功。

## 验证与验收

### 功能测试

- 新建每一种预设情绪的记录。
- 新建“其他”自定义情绪记录。
- 旧记录自动显示为“生气”，内容不丢失。
- 随机打开、放回、回应和成长记录筛选均正常。
- 刷新页面后记录仍然存在。

### 响应式验证

至少检查以下视口：

- 320 × 568
- 360 × 800
- 390 × 844
- 768 × 1024
- 1024 × 768
- 1366 × 768
- 1920 × 1080

每个视口必须满足：无水平滚动、无内容重叠、无不可见主按钮、文字不被裁剪、弹性布局不跳列。

### 自动化与视觉检查

- 为数据规范化、旧数据迁移、情绪校验和筛选补充单元测试。
- 保持现有测试全部通过。
- 对手机、平板和桌面关键页面生成截图并进行人工视觉检查。
- 发布后验证 GitHub Pages 返回最新构建，并抽查核心交互。

## 不在本阶段范围内

- 用户注册和登录。
- 跨设备同步。
- 云端数据库。
- 管理后台。
- 多用户数据管理。
- 对原生移动应用进行单独开发。
